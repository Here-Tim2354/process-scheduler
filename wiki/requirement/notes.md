# 课程要求与报告注意事项

## 一、课程基本要求

课程名称：《操作系统分析与设计实习》

课程周期：2 周。

课程学分：2 学分。

考核方式：实际操作 + 程序运行 + 课程设计报告。

课程目标：

1. 通过实践验证课堂中的操作系统理论；
2. 学会设计简单的综合应用程序或小型模拟操作系统；
3. 理解操作系统的特点、基本设计方法和系统工作原理；
4. 训练问题分析、总体结构设计、用户界面设计、程序实现、测试和报告整理能力。

## 二、选题与实现原则

指导书一共提供六个题目，题目难度逐级递增：

1. 题目一难度最小；
2. 题目六难度最大；
3. 前四个题目需要单独完成；
4. 题目五、题目六可以组队完成；
5. 题目五建议 2 到 3 人一队；
6. 题目六建议 3 到 5 人一队。

本项目选择的是：**题目四：单处理器系统的进程调度**，因此应按单人题目处理。

实现时不要求操作真实操作系统中的数据结构，而是对自己设置的数据结构进行操作，例如数组、链表或队列，用来模拟操作系统中的算法或调度行为。

指导书允许采用任何熟悉的语言编写。因此，本项目采用 Next.js / TypeScript 开发，只要能够清楚模拟 PCB、就绪队列和调度算法，并能展示运行结果，就符合“模拟实现”的基本方向。

## 四、实验开发步骤

指导书要求按照较规范的软件开发过程完成实验。虽然课程题目不如真实工程复杂，但仍应遵循以下步骤。

### 1. 问题分析和任务定义

在设计之前，需要充分分析和理解问题，明确程序要做什么、限制条件是什么。

这一阶段强调“做什么”，而不是“怎么做”。

需要明确：

1. 输入数据的类型；
2. 输入值的范围；
3. 输入形式；
4. 输出数据的类型；
5. 输出值的范围；
6. 输出形式；
7. 如果存在会话式输入，需要明确结束标志；
8. 是否接受非法输入；
9. 对非法输入的反馈方式；
10. 为调试准备测试数据，包括合法输入和非法输入。

对本项目而言，需要特别明确：

1. 进程数量范围；
2. PCB 容量上限；
3. 进程标识符生成方式；
4. 优先数范围；
5. 剩余运行时间范围；
6. 四种调度算法的输入条件；
7. 动态随机生成新进程的触发规则；
8. 页面上应展示哪些运行结果。

### 2. 逻辑设计和详细设计

设计阶段分为逻辑设计和详细设计。

逻辑设计要求：

1. 定义问题中涉及的操作对象对应的数据类型；
2. 按照以数据结构为中心的原则划分模块；
3. 定义主程序模块和各抽象数据类型；
4. 写出每个抽象数据类型的定义；
5. 描述数据结构；
6. 说明每个基本操作的功能；
7. 写出主要模块的算法；
8. 画出模块之间的调用关系图。

详细设计要求：

1. 定义对应的数据存储结构；
2. 写出各函数的伪码算法；
3. 对数据结构和基本操作进一步求精；
4. 写出函数形式的算法框架；
5. 不要过早陷入具体语言细节；
6. 尽量保持系统结构清晰、合理、简单、易于调试；
7. 尽可能做到数据封装；
8. 基本操作的规格说明要明确具体。

对本项目而言，报告中需要重点解释：

1. PCB 类型设计；
2. 就绪队列设计；
3. 空闲 PCB 队列设计；
4. 运行进程指针设计；
5. 进程创建原语；
6. 进程调度原语；
7. 四种调度算法的模块划分；
8. Next.js 页面组件和调度核心逻辑之间的调用关系。

### 3. 编码实现和静态检查

编码是把详细设计结果进一步落实为程序。

在上机调试之前，需要进行静态检查。静态检查主要有两种方式：

1. 用一组测试数据手工执行程序，通常应先分模块检查；
2. 深入理解程序逻辑，在过程中加入注解和断言。

对本项目而言，应在正式运行前检查：

1. 调度算法是否会出现死循环；
2. 队列是否可能丢失进程；
3. 已终止进程是否还会被重新调度；
4. 优先数调度是否每次运行后正确降低优先数；
5. 最短进程优先是否为非抢占式；
6. 最短剩余时间优先是否体现抢占式特征；
7. 随机生成进程是否满足唯一 PID；
8. 页面状态是否和调度核心状态一致。

### 4. 上机准备和上机调试

上机准备包括：

1. 注意不同高级语言文本之间的差别；
2. 熟悉机器的操作系统和语言集成环境；
3. 掌握常用命令操作；
4. 掌握调试工具；
5. 设计测试数据；
6. 手工得出正确结果；
7. 调试最好分模块进行，自底向上，先调试低层函数；
8. 调试正确后，整理源程序和注释，形成格式、风格良好的源程序清单和结果。

对本项目而言，建议调试顺序为：

1. 先测试纯调度函数；
2. 再测试进程创建逻辑；
3. 再测试单步调度；
4. 再测试自动运行；
5. 最后测试界面展示、算法切换和重置功能。

### 5. 总结和整理实验报告

指导书特别提醒：报告的各种文档资料应在程序开发过程中逐渐充实形成，而不是最后补写。

这意味着项目开发时就应同步保留：

1. 需求分析记录；
2. 数据结构设计记录；
3. 算法伪码；
4. 调试问题记录；
5. 测试数据；
6. 运行截图；
7. 用户使用说明。

## 五、课程设计报告结构

报告开头应包含成绩单表格，并填写班级、学号、姓名、题目等信息。成绩单之后另起一页，开始报告主体。

报告主体包括以下六个部分。

### 1. 需求分析

需要明确陈述程序设计任务，强调程序要做什么。

主要包括：

1. 输入的形式和输入值范围；
2. 输出的形式；
3. 程序所能达到的功能；
4. 测试数据，包括正确输入及其输出结果，也包括含有错误的输入及其输出结果。

### 2. 概要设计

需要说明：

1. 程序中用到的所有抽象数据类型的定义；
2. 主程序流程；
3. 各程序模块之间的层次关系；
4. 各程序模块之间的调用关系。

### 3. 详细设计

需要实现概要设计中定义的所有数据类型。

要求：

1. 对每个操作写出伪码算法；
2. 对主程序写出伪码算法；
3. 对其他模块也写出伪码算法；
4. 伪码算法的详细程度应达到能够按照伪码在键盘上直接输入高级程序设计语言程序的程度；
5. 画出函数调用关系图。

### 4. 调试分析

内容包括：

1. 调试过程中遇到的问题；
2. 问题是如何解决的；
3. 对设计与实现的讨论和分析；
4. 算法的时间复杂性，包括基本操作和其他算法的时间复杂性；
5. 改进设想；
6. 设计过程的经验和体会；
7. 实现过程中出现的主要问题及解决方法。

### 5. 用户使用说明

说明如何使用编写的程序，并详细列出每一步操作步骤。

对本项目而言，应包含：

1. 如何启动项目；
2. 如何选择调度算法；
3. 如何生成进程；
4. 如何单步执行；
5. 如何自动运行；
6. 如何暂停和重置；
7. 如何查看当前运行进程、就绪队列、终止队列和调度日志。

### 6. 测试与运行结果

需要列出测试结果和运行情况，即运行时的关键画面，包括输入和输出。

指导书强调：这里的测试数据应该完整和严格，最好多于需求分析中所列。

对本项目而言，建议至少准备：

1. 时间片轮转调度测试；
2. 优先数调度测试；
3. 最短进程优先测试；
4. 最短剩余时间优先测试；
5. 空队列测试；
6. PCB 数量达到上限测试；
7. 单个进程测试；
8. 多个相同剩余时间进程测试；
9. 动态生成新进程测试；
10. 非法输入或边界输入测试。

必要时可在报告中附部分关键源代码，但不需要附全部源代码。

## 六、课程考核比例

课程考核点如下：

1. 编程：50 分；
2. 测试分析：20 分；
3. 报告：30 分。

因此，本项目不能只把界面做出来，还需要保证：

1. 四种算法实现正确；
2. 测试数据完整；
3. 调试分析写清楚；
4. 报告结构完整；
5. 运行结果可截图、可复现、可解释。

个人文件夹命名格式示例：

201631000101陈陈

命名规则：

1. 只包含学号和姓名；
2. 学号和姓名之间没有空格；
3. 学号和姓名之间没有其他符号。

## 九、对本项目的直接注意事项

结合题目四和课程第一部分要求，`process-scheduler` 项目应特别注意：

1. 不能只做静态展示，必须能真实执行四种调度算法；
2. 每次调度应显示当前运行进程的进程标识符、优先数、剩余运行时间等信息；
3. 应能动态随机生成新进程并加入就绪队列；
4. 算法核心要清晰，最好和界面组件分离，方便报告中说明模块关系；
5. 测试数据要能复现，随机数据最好允许固定种子或导出日志；
6. 报告中必须写清楚输入、输出、功能、测试数据、概要设计、详细设计、调试分析、使用说明和运行结果；
7. 报告不要最后补写，开发过程中就应持续整理运行截图和调试问题；
8. 因为编程占 50 分，测试分析占 20 分，报告占 30 分，所以实现、测试、文档三者都要留出时间；
9. 如果使用 Next.js，需要说明它在本项目中只是作为图形化交互界面和模拟器承载方式，核心仍然是操作系统进程调度算法模拟；
10. 如果老师要求“可执行程序”，需要提前决定交付方式，例如提供本地启动脚本、构建后的静态页面，或进一步打包为桌面应用。
