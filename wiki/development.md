# 技术栈

这个项目不只是在完成课程设计，也顺便练一次比较现代的前端工程。

课程要求的重点是四种调度算法、PCB、就绪队列和运行结果。前端这边不需要自己从零造一套 UI 系统，优先用成熟生态，把精力放在页面组织、状态流和交互表达上。

但这个项目不能只做成漂亮页面。课程设计里真正要交代清楚的是“单处理器系统如何组织进程、创建进程、完成调度”。

## 硬性要求

程序里至少要看得出这些东西，并且有明确的文件分类和良好的命名：

- PCB：进程标识符、状态、优先数、剩余运行时间，以及用于模拟队列关系的信息。
- PCB 区：用一组数据结构模拟有限数量的进程控制块。
- 空闲 PCB 队列：创建进程前要先申请空闲控制块，不能无限生成。
- 就绪队列：不同算法只是改变进程进入和离开就绪队列的规则。
- 运行进程指针：每次调度都要明确当前哪个进程正在运行。
- 进程创建原语：随机生成唯一 PID、优先数、运行时间，并把进程挂入就绪队列。
- 进程调度原语：从就绪队列取出进程，运行一次或运行到结束，再决定回队列还是终止。

四种算法都要能真实跑：

- 时间片轮转：队首运行一个时间片，未结束则回到队尾。
- 优先数调度：大数优先，运行后优先数和剩余时间都减 1。
- 最短进程优先：非抢占，选中后直接运行到结束。
- 最短剩余时间优先：按剩余时间排序，每次运行一个时间片。

页面展示要围绕这些要求来做。每次调度至少能看到当前运行进程、优先数、剩余运行时间、就绪队列变化和终止情况。

## 技术组合

```txt
Next.js
TypeScript
Tailwind CSS
shadcn/ui
shadcn/ui Blocks
lucide-react
React Hook Form
Zod
Zustand
Recharts
motion
Vitest
Playwright
```

`Next.js + TypeScript` 负责项目骨架和类型约束。PCB、队列、调度日志这些结构都应该有明确类型。

后续可以考虑 `Electron`，但它先不进入第一阶段。当前先把 Web 版做好；如果老师强调“可执行程序”，再把已有 Next.js 页面包成桌面应用。这样不会一开始就被桌面端工程复杂度拖住。

`Tailwind CSS + shadcn/ui` 负责界面。这里不再引入 Ant Design、MUI、Mantine 这类完整组件库，避免视觉体系混乱。

`shadcn/ui Blocks` 直接作为页面起点，优先使用官方 dashboard block：

```bash
npx shadcn@latest add dashboard-01
```

这个项目本来就像一个调度实验台，dashboard 比 landing page 更合适。

`lucide-react` 用来处理图标。运行、暂停、重置、生成进程、切换算法这些操作都应该有清楚的图标反馈。

`React Hook Form + Zod` 用来处理配置表单，比如进程数量、优先数范围、运行时间范围、PCB 容量和随机种子。

`Zustand` 用来保存模拟器状态。调度算法本身不要写进 store，store 只负责连接 UI 和纯逻辑。

`Recharts` 用来展示调度结果，比如时间线、等待时间、周转时间和算法对比。

`motion` 只做轻量动效。进程进入运行区、回到队尾、进入终止区，这些变化可以有一点动画，但不要抢内容。

`Vitest + Playwright` 用来保证算法和页面都能验。四种调度算法必须能被单独测试。

以及一系列他们的官方文档用于指导。
# 结构原则

算法核心和界面分开。

```txt
src/
  app/
  components/
    scheduler/
  lib/
    scheduler/
  stores/
```

`lib/scheduler` 只写调度逻辑，不碰 React。

`components/scheduler` 负责展示当前运行进程、就绪队列、终止队列、调度日志和统计图表。

`stores` 负责页面状态，不负责解释算法。

# 页面方向

第一屏直接是模拟器。

左侧放算法和配置，顶部放运行状态和操作按钮，中间展示当前运行进程和队列，下方展示调度日志与时间线。

页面要清楚、现代、可解释。不要做花哨介绍页，也不要把课程设计做成纯静态展示。

另外要留出报告材料入口。至少要方便截图：初始进程、单步调度过程、四种算法结果、边界输入提示、PCB 上限提示。

# 动效原则

动效只服务状态理解，不做装饰。

使用 `motion` 的 `layout` 处理进程卡片在就绪队列、运行区、终止区之间的位置变化。新增进程、进程终止、日志追加只做轻量淡入淡出。

当前运行进程只做轻微强调，例如边框、背景和剩余时间变化。图表使用 `Recharts` 自带过渡即可。

不做粒子、发光背景、拖拽动画和持续循环动效。

# 开发顺序

1. 先写 PCB、队列、进程创建和四种调度算法。
2. 给调度算法补单元测试。
3. 接入 Zustand。
4. 用 shadcn dashboard block 搭页面。
5. 接入配置表单、队列展示、日志和图表。
6. 最后做动效、截图和报告材料。
